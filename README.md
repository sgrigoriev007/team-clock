# Team Clock

Небольшое веб-приложение для учёта рабочего времени сотрудников. Тестовое задание: сотрудники, таймеры задач, история и итоговое время за выбранный период, сохранение данных после перезапуска.

**Python 3.11+ · SQLite · Vanilla JavaScript · без сторонних зависимостей и платных сервисов.**

## Быстрый запуск

```bash
git clone https://github.com/sgrigoriev007/team-clock.git
cd team-clock
python3 app.py
```

Откройте **http://127.0.0.1:8000**. На Windows используйте `python app.py`. Установка пакетов, API-ключи и настройка базы не нужны. При первом запуске база создаётся автоматически в `data/team-clock.sqlite3`. Все данные изначально отсутствуют; приложение не создаёт вымышленные отчёты.

Альтернативный запуск:

```bash
docker compose up --build -d
```

Docker хранит SQLite в именованном томе `clock-data`. `docker compose down` сохраняет данные, а `docker compose down -v` удаляет том вместе с данными. Контейнер запускается непривилегированным пользователем. Docker-вариант предоставлен для удобства; проверенный локально путь — прямой запуск Python.

## Возможности

- Добавление сотрудников и проверка повторяющихся имён.
- Запуск задачи с обязательным описанием; одновременно один таймер на сотрудника.
- Одновременная работа разных сотрудников.
- Живой счётчик и остановка таймера. Повторная остановка не изменяет сохранённое время.
- История задач, фильтрация по сотруднику и датам, общее время и итоги по каждому сотруднику.
- CSV-отчёт по тому же фильтру, с защитой текстовых полей от формул электронных таблиц.
- Сохранение сотрудников, задач и активных таймеров в SQLite. Обновление страницы, закрытие браузера или перезапуск сервера не сбрасывают таймер.
- Адаптивный интерфейс на русском языке, подписи полей, клавиатурная навигация и сообщения об ошибках.

## Как проверить за несколько минут

1. Добавьте двух сотрудников.
2. Выберите первого, введите описание и запустите таймер.
3. Попытайтесь запустить второй таймер тому же сотруднику: получите понятную ошибку, первая задача продолжит работу.
4. Запустите задачу второму сотруднику: оба таймера работают независимо.
5. Обновите страницу и перезапустите сервер: активные задачи и отсчёт сохраняются.
6. Остановите задачу, выберите сотрудника и период. Проверьте историю, сумму времени и CSV.
7. Откройте приложение в узком окне или на телефоне через локальную сеть.

Для доступа из локальной сети: `python3 app.py --host 0.0.0.0`. По умолчанию сервер доступен только на текущем компьютере.

## Правила расчёта

Данные хранятся как Unix timestamps, даты отчёта трактуются в **UTC** и включают оба выбранных дня. Начало периода включено, конец — начало следующего дня. Для задачи, пересекающей границу, считается только пересечение с периодом. Например, задача с 23:30 до 01:30 даст 30 минут за первый день и 90 минут за второй. Активные задачи включены в отчёт по серверному времени на момент запроса.

Общее время — сумма времени сотрудников, поэтому два человека, работающие час параллельно, дают два человеко-часа. Расчёт ведётся без поминутного округления; интерфейс показывает полные секунды, CSV — секунды с миллисекундами. Итоги обновляются раз в 10 секунд, активные счётчики — каждую секунду.

Таймеры продолжаются и во время остановки сервера: сохраняется момент начала, а не счётчик в памяти. Это намеренное правило задания, а не автоматическая фиксация реальной активности. Изменение системных часов может повлиять на измерение; серверу нужна корректная синхронизация времени.

## Устройство проекта и решения

```text
app.py                  HTTP API, валидация, SQLite, расчёт отчёта
static/index.html       Семантический интерфейс
static/style.css        Адаптивное оформление
static/app.js           Формы, таймеры, фильтры, обновление данных
tests/test_app.py       Тесты бизнес-логики и реального HTTP API
compose.yaml            Необязательный контейнерный запуск
```

Стандартная библиотека Python выбрана для запуска одной командой без установки пакетов. SQLite достаточно для небольшой демонстрации; сервер остаётся источником истины для времени и данных. SQL-запросы параметризованы. Уникальный частичный индекс гарантирует один активный таймер на сотрудника даже при конкурентных запросах. WAL и отдельное соединение на операцию позволяют обслуживать параллельные запросы.

Тексты пользователей выводятся через `textContent`, без HTML-интерполяции. Статические файлы выдаются по фиксированному списку путей. Установлена Content Security Policy; внешние шрифты, аналитика и CDN не используются. API ограничивает длину полей и размер JSON, отклоняет запросы браузера с другого Origin.

Для маленького задания намеренно не добавлены ORM, сборщик фронтенда, Redis, фоновые задачи и микросервисы. Компромисс: отчёт агрегируется в Python и возвращает всю историю без пагинации. При росте данных нужны SQL-агрегация пересечений, пагинация и соответствующие индексы. `http.server` подходит для локального демонстрационного запуска; для публичного production-сервиса следует перейти на поддерживаемый WSGI/ASGI-стек.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/state?employee_id=1&from=2026-01-01&to=2026-01-31` | Сотрудники, активные таймеры, история и итоги; фильтры необязательны |
| POST | `/api/employees` | `{"name":"Анна"}` |
| POST | `/api/timers/start` | `{"employee_id":1,"description":"Интеграция API"}` |
| POST | `/api/timers/stop` | `{"entry_id":1}` |
| GET | `/api/export.csv` | CSV; принимает те же фильтры |

Ошибки возвращаются в формате `{"error":"Сообщение"}` с кодом 400, 403, 404, 409, 413 или 415. Авторизация и роли не реализованы согласно ограниченному объёму задания. Приложение использует только введённые пользователем данные. Это локальная демонстрация: до размещения в интернете нужны аутентификация, TLS, ограничение запросов и резервное копирование. Не загружайте реальные персональные данные в публичное демо. Рабочая база исключена из Git.

## Тесты

```bash
python3 -m unittest discover -s tests -v
node --check static/app.js
```

Тесты используют временные базы и свободный локальный порт. Проверяют основной цикл, сохранение после повторного открытия базы, конкурентный старт, повторную остановку, ошибки ввода, переход через полночь, фильтры, CSV, статические маршруты и межсайтовые запросы. GitHub Actions запускает тесты на Python 3.11, 3.12 и 3.13. Node нужен только для дополнительной проверки синтаксиса JavaScript, не для запуска приложения.

## Настройки

```bash
python3 app.py --host 127.0.0.1 --port 8080 --db /path/to/clock.sqlite3
```

Также доступны переменные `HOST`, `PORT`, `DATABASE_PATH`. Копировать базу для резервного хранения следует после остановки сервера либо через SQLite backup API; не копируйте только основной файл во время WAL-записи.
